# Backup and recovery

The independent task `aa-at-backup-worker` starts at sign-in and checks the schedule every minute. It writes a ZIP every 24 hours to `D:\AA-AT-Backups`, outside Git. The three slots rotate V1 → V2 → V3 → V1. A replacement is assembled in a temporary file, checked by ZIP CRC, per-file SHA-256, SQLite integrity, and all broker-evidence references before `os.replace` publishes it. On failure, the last valid slot is retained. Each successful slot has a `.manifest.json` and `.sha256` sidecar. The current-worker heartbeat is `backup-heartbeat.json`; a task shown as Running without a fresh heartbeat is not considered healthy. The dashboard's manual button queues an idempotent request in `backup-requests.sqlite3`; it cannot restore data.

The backup includes source and worktrees, campaign runtime, broker evidence, trading journal, wider research folders, account-local command state, research warehouse, collector and backup releases, dashboard release, checkpoint files, and saved task/ACL metadata. Live SQLite files are captured with SQLite's online backup API and validated; WAL/SHM are excluded. Transient locks, generated dependencies and caches are excluded. The host rejected a SYSTEM startup task, so this release uses a current-user sign-in task; it cannot run before that user signs in. The archive is **unencrypted at the user's explicit request** and is restricted by NTFS ACL to the current user, SYSTEM, and Administrators. Do not share it or commit it to Git.

## Isolated verification and restore

Verify an archive with `tools/backup_worker.py`'s ZIP/member digest logic or `ZipFile.testzip()`, compare its `.sha256`, inspect `manifest.json`, and open extracted SQLite snapshots with `PRAGMA integrity_check` in an isolated directory. This is a read-only restore drill. Never restore over a running campaign. A production restore requires explicit authorization, an approved component stop/isolation, current broker position/order reconciliation, preservation of newer deal records, and duplicate-order prevention. Recover source and research state into a **new directory** first; compare checkpoint, Git commit, ledger row IDs, and broker deals before any cutover.

The verified initial V1 archive was created at 2026-10-23 21:02 UTC and contains 395 reconciled closes. V2 and V3 also passed verification; V3 includes the deployed research dashboard and confirms all 8,302 raw research artifacts referenced by its warehouse snapshot. Consult live sidecars for current timestamps and counts rather than this static observation.
