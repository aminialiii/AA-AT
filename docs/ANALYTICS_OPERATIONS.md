# Isolated strategy analytics operations

The separate research warehouse is `E:\GPT\Inves\AA-AT-research-state`; no analytics module imports the trading service or MetaTrader. `research.trade_forensics.priority3` uses SQLite's online backup API to freeze a consistent read-only input, and stores each derived run under `analytics\runs\<analysis-run-id>`. `analytics\latest.json` points to the latest complete report. The daily job refuses a failed backup status. Its calculations are descriptive broker-actual projections; hypothetical fills, if later eligible, must be tagged `COUNTERFACTUAL` and stored outside the DEMO ledger.

The independent Windows task `aa-at-daily-analytics` is installed from `tools/install_analytics_task.ps1` with a frozen Git commit and separate release directory. It runs at user sign-in and daily at 02:30 host local time, ignores overlapping instances, and never manages trading workers. Its `daily-status.json` is under `AA-AT-research-state\analytics`. The dashboard release reads versioned JSON only; it has no analytics write path. A task status of `Ready` after a completed run is normal; verify the status file and timestamp before claiming freshness. Current-user sign-in is required after reboot, as with existing backup and research tasks.

If the analytics report is unavailable, the journal remains readable and analytics tabs show an explicit unavailable state.

Stage dashboard changes by copying the last working dashboard-only release to a new release folder, replacing only reviewed dashboard source/assets, and running `tools/smoke_dashboard_research.py` on a temporary loopback port. The smoke test checks authenticated read-only routes, unauthorized rejection, and stale broker status. Keep the old release intact as rollback. A dashboard task switch must change only `AAATCommandCenter`'s working directory, then verify the running URL and trading task/process state before and after. Never bind publicly or restart the trading service as part of a dashboard release.

Data gates: opaque `.hcc` and `.tkc` cache copies are **not** validated market observations. An offline exporter must prove symbol, timestamp, timezone, Bid/Ask, and gap coverage, and assign a source hash before market importer use. External genuine prices may give explicitly labeled chart context only; they cannot justify broker fill-sensitive counterfactuals. A scenario must register parameters, contract specification and currency conversion, spread/commission/slippage/financing assumptions, finite horizon, acceptance criterion, and chronological holdout before evaluation. Missing values remain `INSUFFICIENT_EVIDENCE`. Same-candle stop/target order is unresolved without ordered ticks.

Neither a later chart nor an optimization result can alter frozen DEMO rules or risk settings. The emergency stop, stale quote gate, S04 breaker, and per-portfolio risk policy remain independent safety controls.
