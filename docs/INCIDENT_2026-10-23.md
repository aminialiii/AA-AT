## What happened

The command-center bridge deployment was attempted during a zero-exposure
maintenance window. The trading scheduled task was disabled and
`research/demo-live-20261021/runtime/EMERGENCY_STOP` was written at
2026-10-23 01:35:24 Asia/Tehran. Its contents explicitly say
`command-center bridge maintenance; no liquidation`. The prior session record
identifies the Codex maintenance operation as the action that disabled the task;
the local Task Scheduler Operational event query did not independently identify
an actor. The user did not initiate the stop. The risk supervisor did not write
this marker as a response to a portfolio halt. Automatic approval review later
denied removal with `blocked by policy`, leaving the stop in force.

The temporary bridge `service.py` was rolled back. The running-workspace
`research/demo-live-20261021/service.py` SHA-256 is
`AFFF706E8C147749A66CFA10D07F640C36A8651DEC8A5D93E794884A1EC5C952`,
identical to the pre-deployment backup in
`AA-AT-command-center-state/rollback/20261023T0135/service.py`. The inert
`worker_control.py` copied during maintenance remains in the runtime directory,
but the restored service does not import it. The command-center process and
Git sync use separate Windows tasks; the dashboard itself did not stop the
trading process. Attempting to couple its command bridge deployment to the
trading task caused the maintenance interruption.
